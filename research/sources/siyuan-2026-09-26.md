## Audit keamanan (CLAUDE.md Tahap 3) - WAJIB

### A. Riset dari sumber resmi (2026-09-26)
1. **Alamat default kernel:** `http://127.0.0.1:6806` (dikonfirmasi di `docs/API.md` resmi §Specification: "Endpoint: `http://127.0.0.1:6806`", dan **diverifikasi hidup-hidup** dengan menjalankan kernel resmi - lihat bagian D di bawah).
2. **Token API:** dilihat di **Settings - Authentication - API token** (dikonfirmasi di `docs/API.md` §Authentication, per 2026-09-26; ini lokasi TERKINI - beberapa tutorial pihak ketiga masih menyebut lokasi lama "Settings - About"; panduan pembeli akan menyebut keduanya karena versi UI bisa beda). Dikirim lewat header `Authorization: Token xxx`.
3. **Kode otorisasi akses ("access auth code" / kata sandi kunci layar):** diatur lewat `--accessAuthCode` (flag CLI) atau field `accessAuthCode` di `conf.json`; kosong secara default pada workspace baru (diverifikasi langsung, lihat bagian D).
4. **Auto-update:** opsional, **Settings - About - "Automatically download update installation package"** (opt-in, bukan otomatis diam-diam berdasarkan deskripsi fitur resmi).
5. **Telemetri/analitik:** tidak ditemukan pengiriman data pemakaian tersembunyi yang didokumentasikan untuk **aplikasi desktop**. **Catatan penting:** issue komunitas resmi #15096 ("Completely remove Google Analytics") menyebut **aplikasi mobile (Android/iOS)** menyertakan Google Analytics yang **opt-out, bukan opt-in** (kritik komunitas terhadap klaim "privacy-first"). Ini **tidak relevan langsung** untuk skill ini (skill hanya memakai kernel desktop lokal, bukan aplikasi mobile), tapi dicatat sebagai **PERLU REVIEW / catatan kejujuran** bila Komunitech nanti merekomendasikan aplikasi mobile SiYuan.
6. **Sinkronisasi cloud:** fitur **opt-in**, butuh akun SiYuan/S3 yang dikonfigurasi manual pengguna; tidak aktif pada workspace baru (dikonfirmasi lewat `conf.json` hasil boot pertama - field `sync` kosong/tidak terisi kredensial).
7. **API endpoint resmi yang dipakai skill** (semua dari `docs/API.md` resmi, commit `master` per 2026-09-26): `/api/notebook/lsNotebooks`, `/api/query/sql` (field `stmt`, BUKAN `sql` - dicatat karena beberapa ringkasan pihak ketiga keliru menyebut `sql`), `/api/filetree/getIDsByHPath`, `/api/filetree/createDocWithMd`, `/api/filetree/removeDocByID`, `/api/block/appendBlock`, `/api/export/exportMdContent`. Lihat `skills/siyuan-sop/references/api-endpoints.md` untuk detail field lengkap.

**Kesimpulan advisory:** dua celah (High & Moderate) di rilis stabil terkini **belum** punya rilis stabil perbaikan per 2026-09-26, TAPI keduanya butuh prasyarat yang **sengaja TIDAK dipakai** dalam alur kerja skill ini: (1) memasang plugin pihak ketiga dari Bazaar, dan (2) mengaktifkan fitur **Publish** (menerbitkan workspace ke jaringan). `docs/panduan-siyuan.md` & `SKILL.md` secara eksplisit melarang/tidak menganjurkan keduanya. Selama pengguna mengikuti panduan (tanpa plugin pihak ketiga, tanpa mengaktifkan Publish/network serving, kernel tetap di 127.0.0.1), kedua celah ini **tidak bisa dieksploitasi lewat jalur yang direkomendasikan skill**.

### C. Yang TIDAK dipakai (sesuai instruksi & prinsip kehati-hatian)
- **Tidak merekomendasikan MCP server komunitas apa pun** (mis. paket MCP pihak ketiga untuk SiYuan). Skill ini memanggil kernel HTTP API resmi **langsung** lewat `scripts/siyuan.py` buatan Komunitech sendiri, yang sudah diaudit baris demi baris (Python standar, tanpa dependensi luar, tanpa `curl | sh`, tanpa membaca file di luar yang diminta pengguna).
- **Tidak memakai server MCP bawaan SiYuan sendiri** (endpoint `/mcp`, `mcpOAuth`) - di luar cakupan skill, mengurangi permukaan serangan (termasuk CVE-2026-66012 di atas, yang notabene khusus jalur `/mcp`, bukan jalur `/api/...` yang dipakai skill ini).

### D. Uji integrasi NYATA dengan kernel resmi (dijalankan, bukan simulasi)
Diunduh **langsung dari GitHub Releases resmi** proyek (`https://github.com/siyuan-note/siyuan/releases/download/v3.8.5/siyuan-3.8.5-linux.tar.gz`, 249.017.675 byte, SHA-256 `532bdf378a5bb53b72937263c015bfa2cd0cdb2ecaa74ca3339c15aefc7df95e` - dicatat untuk rekam jejak; **repo tidak menerbitkan file checksum terpisah** untuk dibandingkan, jadi verifikasi mengandalkan unduhan HTTPS langsung dari domain rilis resmi GitHub, bukan mirror). Biner kernel headless (`resources/kernel/SiYuan-Kernel`, Go, tanpa Electron) dijalankan di sandbox terisolasi (`SiYuan-Kernel serve --workspace <folder-kosong> --port 6806`), **tanpa akses internet keluar dari kernel**, hanya diakses lewat `127.0.0.1` dari `scripts/siyuan.py` dan `curl`.

**Hasil nyata (bukan simulasi):**
1. Kernel v3.8.5 booting sukses, mengonfirmasi log resmi: *"kernel [pid=...] http server [127.0.0.1:6806] is booting"* - **mengikat ke 127.0.0.1**, bukan `0.0.0.0`, sesuai klaim resmi.
2. **Token API dibuat OTOMATIS secara acak saat boot pertama** (field `api.token` di `conf.json`, tidak kosong/tidak dapat ditebak) - kabar baik, bukan default lemah seperti "admin/admin".
3. `accessAuthCode` (kata sandi kunci layar) **kosong secara default** pada workspace baru, sesuai riset.
4. Semua 7 endpoint yang dipakai `siyuan.py` (`lsNotebooks`, `query/sql`, `getIDsByHPath`, `createDocWithMd`, `removeDocByID`, `appendBlock`, `exportMdContent`) **berhasil dipanggil sungguhan** lewat `scripts/siyuan.py`: buat dokumen (judul & isi berisi emoji/Unicode `🕐😊`), baca kembali sebagai Markdown, tambah isi, pencarian teks (termasuk mencari kata yang hanya ada di badan paragraf), proteksi tolak-timpa (`buat` tanpa `--timpa` pada path yang sudah ada → kode keluar 7, sesuai desain), lalu ekspor gabungan basis pengetahuan ke satu file Markdown.
5. **Temuan nyata yang mengubah desain script:** membuat dokumen di path bertingkat (mis. `/FAQ/Jam Buka`) otomatis membuat dokumen **induk kosong** (`/FAQ`) sesuai dokumentasi resmi ("missing parent documents are created automatically"). Perintah `ekspor-basis` awalnya ikut menyertakan dokumen induk kosong ini sebagai entri terpisah (noise). **Diperbaiki** di `scripts/siyuan.py` (fungsi `_kosong`) untuk melewati dokumen yang hanya berisi frontmatter + judul otomatis tanpa isi asli - diverifikasi ulang lewat kernel yang sama sampai hasilnya benar (hanya dokumen berisi yang muncul di file gabungan).
6. **TEMUAN KEAMANAN PENTING (baru, hasil uji langsung, belum ditemukan didokumentasikan resmi):** permintaan ke endpoint `/api/...` (mis. `lsNotebooks`, `query/sql`, bahkan `createNotebook` yang MENULIS) **berhasil TANPA header `Authorization` sama sekali** - bukan hanya token kosong, tapi header itu **tidak ada sama sekali** di permintaan `curl` polos. Mengatur `accessAuthCode` di `conf.json` lalu me-restart kernel **TIDAK mengubah perilaku ini** untuk permintaan tanpa Origin. Saat permintaan yang sama diberi header `Origin` yang menyerupai situs web asing (simulasi serangan "DNS rebinding"/skrip jahat di tab peramban), kernel **menolak** dengan pesan resmi: *"Auth failed: for security reasons, please set [Lock screen password] when using non-127.0.0.1 access"*. **Kesimpulan:** SiYuan tampaknya mempercayai permintaan tanpa header `Origin` gaya peramban (mis. dari `curl`, script CLI biasa, atau aplikasi desktop-nya sendiri) sebagai "aplikasi lokal tepercaya" dan **tidak mewajibkan token API untuk jalur ini**, sementara proteksi anti-DNS-rebinding baru aktif bila ada header `Origin` asing. **Ini berarti token API bukan pembatas keamanan utama** terhadap proses/pengguna LAIN di komputer yang sama yang bisa memanggil `127.0.0.1:6806` langsung (bukan lewat peramban) - pembatas keamanan yang sebenarnya adalah **kernel hanya bisa dijangkau dari komputer itu sendiri**. Ini BUKAN bug yang bisa dilaporkan sebagai CVE baru dalam audit ini (butuh konfirmasi lebih lanjut dari tim SiYuan, di luar cakupan tugas), tapi **wajib** disampaikan apa adanya ke pembeli di `docs/panduan-siyuan.md` dan `SKILL.md`, karena mengubah rekomendasi keamanan: **jangan pernah menjalankan software tidak tepercaya di komputer yang sama dengan SiYuan**, dan **jangan pernah membagi komputer/akun OS itu dengan orang yang tidak berhak melihat basis pengetahuan**.
7. Kernel menyajikan HTTP **dan** HTTPS (sertifikat CA lokal yang dibuat otomatis) sekaligus di port yang sama; `http://127.0.0.1:6806` (tanpa TLS) tetap berfungsi dan sesuai contoh resmi di `docs/API.md`, jadi skill memakai alamat default itu.

## Keputusan
**LULUS AUDIT dengan syarat wajib (mitigasi didokumentasikan, bukan ditolak).** Tidak ada risiko yang TIDAK bisa dimitigasi lewat panduan pemakaian:
- Kernel **WAJIB** tetap di `127.0.0.1` (default), **JANGAN PERNAH** diaktifkan "network serving" ke `0.0.0.0`/dibuka ke jaringan, dan **JANGAN PERNAH** di-port-forward ke internet (mitigasi CVE Publish-related & temuan D6).
- **JANGAN memasang plugin pihak ketiga** dari Bazaar SiYuan (mitigasi GHSA-phmw, celah baca-file lewat plugin jahat).
- **JANGAN mengaktifkan fitur Publish** (menerbitkan ke web) untuk kebutuhan basis pengetahuan internal ini (mitigasi GHSA-cxwr & beberapa advisory "Publish reader" lain yang ditemukan di listing tapi tidak dirinci di sini karena semuanya butuh Publish aktif).
- Set **kata sandi kunci layar (accessAuthCode)** dan simpan **token API** dengan benar (tidak pernah ditempel di chat/skill/log) - lapis pertahanan tambahan meski temuan D6 menunjukkan token bukan satu-satunya pembatas.
- **Jangan bagikan komputer/akun OS** yang menjalankan SiYuan dengan pihak yang tidak berhak (temuan D6).
- Perbarui SiYuan begitu **v3.8.6 stabil** dirilis (menutup GHSA-phmw & GHSA-cxwr secara resmi).
- Tidak ada MCP komunitas yang direkomendasikan; skill memanggil kernel API resmi langsung.

`skor_kualitas` katalog dikosongkan sesuai proses (diisi penguji independen setelah Tahap 6).
