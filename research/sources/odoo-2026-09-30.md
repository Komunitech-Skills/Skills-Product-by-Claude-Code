## 2. API eksternal resmi (dasar desain skill)
URL yang dibaca (30 Sep 2026):
- https://www.odoo.com/documentation/19.0/developer/reference/external_api.html (JSON-2)
- https://www.odoo.com/documentation/19.0/developer/reference/external_rpc_api.html (XML-RPC/JSON-RPC)
- https://www.odoo.com/documentation/18.0/developer/reference/external_api.html (XML-RPC, versi 18)
- Sumber `.rst`: https://raw.githubusercontent.com/odoo/documentation/19.0/content/developer/reference/external_api.rst, `.../20.0/.../external_api.rst`, `.../20.0/.../external_rpc_api.rst`
- Docker: https://raw.githubusercontent.com/docker-library/docs/master/odoo/content.md, https://raw.githubusercontent.com/odoo/docker/master/19.0/entrypoint.sh

Fakta yang dipakai (parafrase, bukan kutipan panjang):
1. **JSON-2 (Odoo 19+):** `POST /json/2/<model>/<method>`, header `Authorization: bearer <API key>`, `Content-Type: application/json`, opsional `X-Odoo-Database` (server multi-database). Body = objek JSON berisi `ids`, `context`, dan parameter bernama metode (mis. `domain`, `fields`, `limit`). Sukses = 200 + nilai kembali JSON; galat = 4xx/5xx + objek `{name, message, arguments, context, debug}` (contoh 401 "Invalid apikey"). ID pengguna dari `res.users/context_get`. Versi server: `GET /web/version` → `{"version_info": [...], "version": "19.0"}`.
2. **XML-RPC:** `/xmlrpc/2/common` (`version`, `authenticate(db, login, password/kunci, {})` → uid) dan `/xmlrpc/2/object` (`execute_kw(db, uid, kunci, model, metode, args, kw)`). Kunci API dapat menggantikan sandi sejak Odoo 14.
3. **Jadwal penghapusan (dokumentasi 20.0):** XML-RPC & JSON-RPC (`/xmlrpc`, `/xmlrpc/2`, `/jsonrpc`) usang sejak 19.0; layanan `db` dihapus di Odoo 20 (fall 2026) & Online 19.1; layanan `common` & `object` dijadwalkan dihapus di **Odoo 22 (fall 2028)** dan **Online 21.1 (winter 2027)**. → skill memilih JSON-2 otomatis untuk 19+, XML-RPC untuk 16–18.
4. **Paket:** "Access to data via the external API is only available on *Custom* Odoo pricing plans" — tidak tersedia di *One App Free*/*Standard* (Odoo Online). → disampaikan di README/panduan/SKILL.
5. **Kunci API:** dibuat di Preferensi → Keamanan Akun → Kunci API Baru; tampil sekali; Odoo 19 mewajibkan durasi (maks. tiga bulan untuk pembuatan lewat UI menurut dokumentasi; batas mengikuti peran pengguna). Dokumentasi menyarankan **pengguna bot khusus** berhak minimal.
6. Hak akses API = hak pengguna biasa (access rights, record rules).

Model/field yang dipakai skill (dari pengetahuan ORM standar, **belum diverifikasi terhadap server asli** — lihat §4): `sale.order` (`state`, `date_order` UTC, `amount_*`, `currency_id`, `origin`, `validity_date`), `sale.order.line`, `account.move` (`move_type`, `state`, `payment_state`, `invoice_date(_due)`, `amount_*_signed`), `stock.warehouse.orderpoint` (`product_min_qty`, `product_max_qty`, `qty_on_hand`, `qty_forecast`), `product.product` (`is_storable` 18+ / `type='product'` ≤17, `qty_available`, `virtual_available`), `res.partner` (`mobile` dianggap hilang di 19 → dicek lewat `fields_get`).

## 3. Keputusan lisensi & posisi hukum
- Skill **tidak mendistribusikan, menyalin, atau memodifikasi kode Odoo**; ia program terpisah yang memanggil API server milik pembeli. Tidak ada kutipan kode/dokumentasi di skill (hanya nama endpoint/field teknis yang diperlukan untuk interoperabilitas).
- Hasil = **karya orisinal Komunitech**, lisensi Proprietary Komunitech (`skills/odoo-usaha/LICENSE`). Keterangan **"tidak berafiliasi dengan Odoo S.A."** di LICENSE, README, dan panduan (keputusan pemilik 2026-09-26: merek pihak ketiga boleh sebagai penyebut produk + keterangan tidak berafiliasi).
- `docs/panduan-odoo.md` hanya merujuk perintah Docker dari dokumentasi image resmi (ditambah pengikatan `127.0.0.1`).

## 4. Audit keamanan & kejujuran uji
- Tidak ada kode pihak ketiga yang dijalankan. Tidak ada server Odoo asli di sesi ini → dibuat **server tiruan** stdlib (`skills/odoo-usaha/tests/server_tiruan.py`) yang meniru bentuk XML-RPC (Fault kode 1–4 seperti `/xmlrpc/2`) dan JSON-2 (status + objek galat) sesuai dokumentasi; data fiktif. Perilaku pajak & pembulatan server tiruan hanyalah pendekatan.
- **Risiko terbuka (PERLU REVIEW sebelum `lulus`):** nama field/perilaku di Odoo asli 16–20 (terutama `qty_on_hand/qty_forecast` di orderpoint, `payment_state='in_payment'`, argumen `fields_get(attributes=...)` via JSON-2, format galat JSON-2 404/422), kunci API kedaluwarsa, dan Odoo Online paket Custom. Uji lanjutan disarankan: Odoo Community 17 & 19 lewat Docker resmi di sandbox (data fiktif), rekam respons jadi fixture.
