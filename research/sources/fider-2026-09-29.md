## REST API resmi (dibaca 29 Sep 2026; lalu DIUJI pada instance v0.38.0 asli)
Dokumentasi: https://docs.fider.io/api/posts , /comments , /tags , /votes , /authentication ; kode rute `app/cmd/routes.go` (tag v0.38.0).
- Auth: `Authorization: Bearer <kunci API>`; kunci dibuat di Fider (profil > Settings > API Key), hanya Collaborator/Administrator. Header `X-Fider-UserID` (impersonasi) **tidak dipakai** skill.
- Posts: `GET /api/v1/posts` (query `query`, `view`, `limit` [angka atau `all`, bawaan 30], `tags`); `GET/POST /api/v1/posts`, `GET/PUT/DELETE /api/v1/posts/{nomor}`; status: `PUT /api/v1/posts/{nomor}/status` (`status`, `text`, `originalNumber` untuk duplicate).
- Votes: `GET/POST/DELETE /api/v1/posts/{nomor}/votes` (daftar = Collaborator+).
- Comments: `GET/POST /api/v1/posts/{nomor}/comments`, `PUT/DELETE .../comments/{id}`.
- Tags: `GET/POST /api/v1/tags` (Admin), `PUT/DELETE /api/v1/tags/{slug}`, `POST/DELETE /api/v1/posts/{nomor}/tags/{slug}`.

## Temuan uji nyata (Fider v0.38.0 + PostgreSQL 17, Docker, 29 Sep 2026)
- Status sah: `open, planned, started, completed, declined, duplicate`. **Status asing (mis. "bogus") diterima HTTP 200 lalu diam-diam jadi `open`** → skill memvalidasi sendiri.
- Kunci API salah → HTTP 400 `API Key is invalid` (bukan 401); tanpa kunci ke `/api/v1/users` → 401 (halaman HTML). Endpoint baca publik (`GET /posts`) tetap 200 tanpa kunci → `cek` memakai tag+pos+users untuk memastikan kunci sah.
- `view=all` **mengabaikan** parameter `statuses` (pakai daftar tetap open/started/planned/completed/declined); view lain membatasi ke open/planned/started → skill menyaring status di sisi klien. Pos `duplicate` tidak muncul di daftar.
- Judul pos maksimum **100 karakter** (100 = 200 OK, 101 = 400).
- Pos yang dibuat lewat API otomatis mendapat 1 suara dari pemilik kunci (dapat dihapus lewat `DELETE .../votes`).
- Menggabung (`status=duplicate` + `originalNumber`) memindahkan suara ke pos induk (suara pemilik yang sama tidak dihitung dua kali).
- Pembuatan situs awal (wizard `/signup`) memerlukan email verifikasi → butuh SMTP; pada uji dipakai server SMTP tiruan lokal.

## Audit keamanan (Tahap 3)
- Dibaca: `.example.env`, `docker-compose.yml` repo (hanya sebagai referensi env), `Dockerfile` (`./fider migrate && ./fider`), rute API. Image dijalankan tanpa `curl | bash`; tidak ada unduhan skrip saat menyala.
- Port aplikasi 3000 → panduan memetakan ke `127.0.0.1` dan menaruh HTTPS (Caddy) di depannya bila dipublikasikan.
- Papan Fider **publik secara bawaan** → skill menyamarkan nomor HP/email dari catatan WA sebelum menulis (kepatuhan UU PDP); pengaturan "situs privat" dijelaskan di panduan.
