## 3. Cara verifikasi (kejujuran metodologi) — lebih jauh dari sekadar baca dokumentasi

Berbeda dengan riset Grist (2026-09-26) yang **tidak bisa** menjalankan Docker di sandbox ini, untuk Vikunja kami **berhasil mengunduh dan MENJALANKAN binary resmi sungguhan**:

1. Repo `go-vikunja/vikunja` di-*clone* dangkal (`--depth 1`, akses baca publik lewat proxy sesi) ke luar folder produk untuk membaca kode sumber asli: routing (`pkg/routes/routes.go`), model token & permission (`pkg/models/api_tokens.go`, `api_tokens_permissions.go`, `api_routes.go`), model task (`pkg/models/tasks.go`), konfigurasi (`pkg/config/config.go`). **Tidak ada kode yang disalin** ke skill; hanya dipakai untuk memastikan nama endpoint/field/permission benar.
2. File biner resmi **diunduh dari domain unduhan resmi Vikunja** `https://dl.vikunja.io/vikunja/v2.6.0/vikunja-v2.6.0-linux-amd64-full.zip` (bukan pihak ketiga; URL ini yang disebut `vikunja.io/docs/installing/` sebagai sumber resmi). Paket berisi file `vikunja-v2.6.0-linux-amd64.sha256` buatan Vikunja sendiri; **checksum SHA-256 dicocokkan dan COCOK** (`sha256sum -c` → `OK`). File `.sig` (tanda tangan GPG) juga ada di server resmi, tapi **verifikasi GPG penuh tidak bisa diselesaikan** di sandbox ini karena `keyserver.ubuntu.com`/`keys.openpgp.org` tidak terjangkau lewat proxy sesi (timeout) — dicatat apa adanya, **bukan diklaim sudah diverifikasi GPG**.
3. Binary **dijalankan sungguhan** (bukan simulasi) di sandbox, terikat ke `127.0.0.1:3456` saja, database SQLite baru, tanpa mailer/tanpa lisensi Pro. Terhadap instance hidup ini kami:
   - Mendaftarkan user via `POST /api/v1/register`, login via `POST /api/v1/login` (JWT).
   - Membuat **API token berskop** via `PUT /api/v1/tokens` dengan body `{"permissions":{"tasks":[...],"projects":[...]},"expires_at":...}` — **mengonfirmasi langsung** format izin (bukan tebakan dari kode): kunci group `tasks`, `projects`, `tasks_assignees`; nilai izin `create`, `read_all`, `read_one`, `update`, `delete`, dan permission khusus non-CRUD seperti `projects.projectusers`. Daftar lengkap per grup diambil dari `GET /api/v1/routes` (endpoint resmi yang disebut dokumentasi sebagai sumber kebenaran daftar izin).
   - Membuat proyek (`PUT /projects`), membuat tugas dengan `due_date` (`PUT /projects/:id/tasks`), **mengambil semua tugas lintas proyek** (`GET /tasks`, bukan `/tasks/all`) dengan query `filter` (bahasa filter Vikunja, mis. `due_date < now && done = false` untuk tugas terlambat), menandai tugas selesai (`POST /tasks/:id` dengan `{"done":true}`), memberi tugas ke anggota (`GET /projects/:id/projectusers` untuk cari id pengguna dari nama, lalu `PUT /tasks/:id/assignees`).
   - Menguji kasus gagal: token salah → `401` `{"code":11,...}`; token yang kekurangan izin (mis. hanya baca, dipakai untuk membuat tugas) → **juga `401` dengan pesan yang SAMA persis** ("missing, malformed, expired or otherwise invalid token provided") — **bukan `403`**. Ini penting: skill tidak bisa membedakan "token salah" dari "token kurang izin" dari kode HTTP saja, jadi pesan error skill akan menyebutkan **kedua kemungkinan**.
   - `GET /api/v1/tasks/9999` (tidak ada) → `404`.
4. Semua hasil di atas **nyata dari server v2.6.0 yang berjalan**, direkam untuk dipakai sebagai contoh di `references/api-vikunja.md` dan sebagai dasar `tests/` (fixture format respons diambil dari sini, bukan dikarang).
5. **Belum/tidak diuji** di sandbox ini: instalasi di Windows/macOS sungguhan (tidak ada mesin itu di sandbox), Docker (daemon Docker diblokir kebijakan sandbox), autentikasi OpenID/SSO, MySQL/Postgres (kami hanya menguji SQLite, yang juga merupakan default & rekomendasi kami untuk UMKM satu-server).

**Repo `go-vikunja/vikunja` yang di-*clone* untuk riset ini ada di luar folder `Skills/` dan tidak pernah ditambahkan ke git repo Komunitech.**

## 4. Keamanan (Tahap 3 CLAUDE.md)

- **Telemetri**: dari `pkg/config/config.go`, satu-satunya opsi pelaporan adalah **Sentry** (`sentry.enabled`, `sentry.frontendenabled`) untuk pelacakan galat, **default `false` (mati)**. **Tidak ada** telemetri "penggunaan anonim" yang menyala default. Aman untuk instalasi lokal tanpa mengirim data ke luar selama Sentry tidak diaktifkan (panduan kami tidak mengaktifkannya).
- **Alamat dengar default**: `service.interface` default **`:3456`** = mendengar di **SEMUA antarmuka jaringan**, bukan hanya komputer sendiri. **Wajib** diubah ke `service.interface: 127.0.0.1:3456` (atau env `VIKUNJA_SERVICE_INTERFACE=127.0.0.1:3456`) — dikonfirmasi lewat kode (`ServiceInterface.setDefault(":3456")`) dan diuji langsung (server yang kami jalankan memang bisa diikat ke `127.0.0.1` dengan opsi ini; log menunjukkan `HTTP server listening on 127.0.0.1:3456`).
- **Database default**: SQLite (`database.type: sqlite`), file tunggal di komputer sendiri — cocok untuk tim kecil satu kantor/jaringan, tanpa server database terpisah.
- **Token API**: prefiks `tk_`, disimpan di server sebagai hash (SHA-256; kolom lama pakai PBKDF2), **teks asli hanya ditampilkan sekali** saat dibuat (`json:"token,omitempty" readOnly`). Skill kami mengikuti pola ini: token tidak pernah dicetak ulang setelah disimpan.
- **Registrasi terbuka**: `service.enableregistration` — jika dibiarkan `true` di server yang bisa diakses orang lain, siapa pun bisa mendaftar. Panduan kami menonaktifkannya setelah akun pemilik dibuat, atau langsung mematikannya bila hanya satu admin yang memakai.
- **CORS**: bawaan mengizinkan origin `127.0.0.1`/`localhost` saja pada instalasi default kami — konsisten dengan "hanya untuk komputer sendiri".

**PERLU REVIEW pemilik:**
- Verifikasi GPG signature biner resmi **tidak selesai** (keyserver tak terjangkau di sandbox) — hanya SHA-256 resmi yang cocok. Sebaiknya diverifikasi ulang oleh pemilik/tim di komputer dengan akses keyserver sebelum status naik ke `uji`/`lulus`.
- Belum diuji instalasi Windows/macOS sungguhan, dan belum diuji Docker sungguhan (kebijakan sandbox). Perlu uji platform asli sesuai `docs/uji-platform.md` sebelum naik status.
- Kuirk "401, bukan 403, untuk token kurang izin" perlu dipantau bila Vikunja mengubah perilaku ini di rilis mendatang (skill sudah menulis pesan yang mencakup kedua kemungkinan, tapi sebutkan ke pemilik sebagai potensi titik rapuh terhadap perubahan versi).
