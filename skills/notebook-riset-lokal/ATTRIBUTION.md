## Tentang Open Notebook
- Skill ini **memanggil REST API resmi** Open Notebook milik pengguna (`/api/...`, header `Authorization: Bearer <kata sandi>` bila server diatur memakai kata sandi). Skill ini adalah program terpisah yang berkomunikasi lewat HTTP; **tidak** menyalin, memodifikasi, atau menyertakan kode Open Notebook.
- **Open Notebook** (https://github.com/lfnovo/open-notebook) berlisensi **MIT** (file `LICENSE` di repo resminya, dicek langsung: "MIT License, Copyright (c) 2024 Luis Novo"). Open Notebook **TIDAK didistribusikan** dalam paket ini; pembeli memasangnya sendiri lewat Docker dari image resmi (`lfnovo/open_notebook`) sesuai `docs/panduan-open-notebook.md`.
- Nama-nama endpoint, format field (`SourceCreate`, `AskRequest`, `PodcastGenerationRequest`, dll.), port bawaan (8502 tampilan web, 5055 API), dan skema autentikasi (`OPEN_NOTEBOOK_PASSWORD` → header `Authorization: Bearer`) diverifikasi dengan **membaca kode sumber resmi** Open Notebook (`git clone --depth 1`, commit `3127f14ea9dbb519f0e4ddc64a0742ca644ba6ef`, tanggal commit 2026-09-13, versi `pyproject.toml` `1.14.0`) di sandbox Komunitech pada 2026-09-26 — folder `api/routers/*.py`, `api/models.py`, `api/podcast_service.py`, `api/auth.py`, `docker-compose.yml`, dan `README.md` resminya. **Tidak ada baris kode Open Notebook yang disalin** ke `scripts/notebook.py`.
- **v1.0.1 — diuji ulang terhadap Open Notebook 1.14.0 ASLI (bukan lagi hanya pembacaan kode).** Penguji independen (Akun B, 2026-09-26) menjalankan server sungguhan **tanpa Docker** di sandbox `.../scratchpad/k8b/`: clone commit `3127f14` yang sama, `uv sync --no-dev`, SurrealDB v2.0.0 (binary resmi rilis GitHub, `surreal start --bind 127.0.0.1:8000`), API (`run_api.py`, `API_HOST=127.0.0.1 API_PORT=5055`) dan `surreal-commands-worker` (pemroses sumber latar belakang, wajib agar `tambah-sumber` benar-benar mengindeks — di image Docker resmi ini jalan otomatis lewat `supervisord.conf`, di luar Docker harus dijalankan manual). Semua koneksi diverifikasi hanya ke `127.0.0.1`; ketiga proses dimatikan di akhir sesi, dikonfirmasi `curl` ke `127.0.0.1:5055`/`:8000` sudah gagal konek.
  - **Bug kritis ditemukan & diperbaiki:** `POST /api/sources` (dependency `parse_source_form_data`, semua field `Form(...)`) **hanya** menerima `multipart/form-data` — v1.0.0 mengirim JSON dan selalu dibalas `422 Field required`. Dibuktikan dengan `curl -F` manual yang berhasil (200 OK) ke server yang sama. `scripts/notebook.py` v1.0.1 mengirim `multipart/form-data` (encode manual pakai `urllib` + boundary, tetap Python standar tanpa paket luar) — **diverifikasi berhasil (200 OK)** untuk tipe `link` maupun `teks`, termasuk sampai `status: completed` setelah worker memprosesnya.
  - **Bug sedang ditemukan & diperbaiki:** respons `POST /api/search` versi 1.14.0 hanya berisi `id`/`parent_id`/`relevance`/`title` — **tidak** ada `parent_type`/`matches`/`content` yang tadinya dibaca `cmd_cari`. Skill sekarang membaca field yang benar-benar ada dan menyebut keterbatasan "tanpa cuplikan" apa adanya.
  - **Dikonfirmasi ulang BENAR** (tanpa perubahan) terhadap server asli yang sama: `cek`, `daftar-notebook`, `buat-notebook` (pratinjau & `--ya`), `daftar-sumber`, penolakan URL non-localhost (diuji dengan alamat TEST-NET nyata), pesan "model AI belum diatur" (memanggil `GET /api/models/defaults` asli), input tidak lengkap, dan tipe `file` ditolak tanpa pernah menghubungi server.
  - `docker-compose.yml` resmi commit `3127f14` dikonfirmasi membuka port `8502`/`5055` tanpa `127.0.0.1:` (persis seperti diklaim `docs/panduan-open-notebook.md` bagian 4); service `surrealdb` di versi ini **sudah** dibatasi `127.0.0.1:8000:8000` oleh upstream.
  - Detail lengkap, log, dan lima skenario uji: `examples/HASIL-UJI.md`, `examples/03-07-*-uji-akun-b.md`.
  - `tests/uji_regresi.py` (server tiruan) diperbarui agar mock **menuntut** `multipart/form-data` untuk `/api/sources` (menolak JSON dengan 422, persis perilaku asli) dan memakai skema `id`/`parent_id`/`relevance`/`title` untuk pencarian — supaya bug sekelas ini tertangkap otomatis oleh 40 skenario regresi ke depannya, bukan lolos diam-diam seperti yang terjadi pada v1.0.0.
  - Belum diuji sesi ini: model AI sungguhan (Ollama/API key — sandbox uji sengaja tanpa model AI untuk menguji jalur "belum diatur"), platform asli (OpenClaw/Codex/Cursor), dan `uji_openclaw.sh`.
- `docs/panduan-open-notebook.md` mengubah contoh `docker-compose.yml` resmi (yang membuka port `8502`/`5055` ke semua jaringan) menjadi dibatasi `127.0.0.1:` saja, mengikuti prinsip keamanan Komunitech — perubahan ini disebutkan secara eksplisit di panduan tersebut.
- "Open Notebook" adalah nama proyek open-source milik pembuatnya (Luis Novo/lfnovo). Komunitech tidak berafiliasi dengan proyek Open Notebook; nama dipakai hanya untuk menjelaskan kompatibilitas.
