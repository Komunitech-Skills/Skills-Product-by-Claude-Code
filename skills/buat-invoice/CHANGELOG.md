# Riwayat perubahan — buat-invoice

Catatan teknis per versi (dipindah dari README agar halaman pembeli ringkas).

## Catatan revisi 1.0.8 (2026-10-17)
Perbaikan cacat yang terlihat pembeli dari uji bot Telegram asli (gelombang G24, 17 Okt 2026, versi 1.0.7: tanpa skill 7,5 → dengan skill 3,5, BELUM). Semua angka di uji itu benar (INV/2026/10/0008, total Rp8.075.000, DP Rp3.000.000, sisa Rp5.075.000, tanpa PPN); rumus dan pembulatan tidak berubah.
- **Penyebab 1 — invoice tidak sampai.** Agent menulis invoice lengkap sebagai pesan antara, lalu memanggil alat untuk melampirkan berkas. Gateway Telegram OpenClaw hanya mengirim **balasan terakhir** giliran, jadi pengguna hanya menerima ringkasan yang menyebut invoice "sudah saya tulis di atas" padahal di atasnya kosong. **Perbaikan:** SKILL.md kini membuka dengan "Aturan balasan": urutan wajib script → lampir berkas → balasan terakhir berisi invoice/kuitansi LENGKAP (nomor, item, diskon, ongkir, subtotal, PPN bila ada, TOTAL, DP, sisa, terbilang, rekening, jatuh tempo, kota/penanda tangan); dilarang "lihat/sudah di atas" atau ringkasan pengganti; tanpa narasi di antara pemanggilan alat. Langkah kerja, blok UNTUK AGENT SAJA, format output, dan checklist ikut diperbarui. Catatan lampiran dari script juga mengingatkan urutan ini.
- **Penyebab 2 — lampiran HTML ditolak.** `OutboundDeliveryError: hostReadCapability permits only validated plain-text documents and trusted generated HTML reports for local reads` (2×, agent mencoba ulang dengan `asDocument`/`mimeType`). Kode OpenClaw 2026.10.2 (`web-media`) hanya menerima HTML dari folder sementara/staging OpenClaw, sedangkan `.txt` teks biasa (UTF-8, >95% karakter tercetak) diterima; dicek lokal dengan fungsi pemuat media OpenClaw: HTML hasil script ditolak, `.txt` diterima. **Perbaikan:** opsi baru `--txt <path>` (aturan `{nomor}`/folder sama dengan `--html`, akhiran `.txt` dipaksa) menulis versi teks biasa bagian dokumen untuk pembeli (tanpa Markdown/tabel, tanpa "Info untuk penjual", angka sama persis) dan mencetak `BERKAS TEKS: <path absolut>` (`txt_disimpan_ke` di JSON). Aturan lampir: `BERKAS:` sekali → bila gagal `BERKAS TEKS:` sekali (maks. dua percobaan, tanpa mengulang dengan opsi lain). HTML tetap format cetak utama.
- **Penyebab 3 — kalimat gagal teknis.** Balasan memakai "File HTML" dan "pembatasan akses baca file di sisi sistem". **Perbaikan:** kalimat status berkas baku berbahasa awam per jenis dokumen (`<dokumen>` = invoice/kuitansi): terkirim / hanya versi teks / lampiran lewat baris di balasan (netral, hasil tidak diketahui) / semua gagal + "balas 'kirim file'" / terminal-IDE (sebut lokasi) / tanpa Python (tidak ada berkas). Di chat tanpa kata HTML, path, folder, sistem, akses baca, error, nama alat, atau nama berkas.
- **Cara melampirkan (temuan pemeriksa independen).** Prompt sistem OpenClaw 2026.10.2 menyuruh agent melampirkan lewat baris `MEDIA:<path>` di balasan terakhir; lewat cara itu agent tidak tahu apakah HTML ditolak, jadi cadangan teks tidak pernah dicoba dan kalimat status bisa mengklaim berhasil. SKILL.md kini: (a) utamakan alat kirim/lampir yang melaporkan berhasil/gagal, dipanggil sebelum balasan terakhir; (b) bila satu-satunya cara adalah baris lampiran di balasan, lampirkan HANYA `BERKAS TEKS:` (satu baris) dengan kalimat netral "Versi teks <dokumen> saya lampirkan di pesan ini; kalau tidak muncul, balas 'kirim file'."; (c) tidak pernah dua baris lampiran untuk dokumen yang sama; kanal yang diketahui menolak berkas siap cetak (OpenClaw) langsung memakai versi teks. Catatan lampiran dari script ikut menyebut ini.
- **"Kirim file" tidak menjalankan ulang script.** Menjalankan ulang dengan `--nomor-terakhir` = nomor baru diam-diam menghasilkan 0009; kini dipakai lagi path `BERKAS:`/`BERKAS TEKS:` yang sudah ada, atau (bila berkas hilang) nomor yang sama di kolom `nomor` (revisi).
- **Lokasi berkas hanya untuk terminal/IDE.** Aturan kerja dan butir `--counter-file` tidak lagi menyuruh menyebut lokasi di chat (cukup "nomor terakhir sudah dicatat"); catatan nomor dari script menandai path file pencatat nomor "hanya untuk terminal/IDE".
- **Isi wajib "bila ada".** Daftar isi dokumen di Aturan balasan & checklist: baris jatuh tempo, diskon, ongkir, PPN, DP, sisa, termin, PPh 23, rekening, meterai hanya bila dicetak script (kuitansi lunas tidak punya); tidak boleh menambah baris kosong/karangan.
- **Contoh SKILL.md** kini menunjukkan balasan terakhir utuh (dokumen persis dari script → catatan untuk penjual dengan kalimat meterai disalin dari script → satu kalimat status berkas), menggantikan contoh "dipersingkat" dengan kalimat meterai tulisan sendiri.
- **Perbaikan HTML lama:** baris info PPh 23 di HTML menampilkan escape Markdown bila nama pembeli memuat `_`/`*` (`PT Maju\_Jaya`); kini tanpa escape Markdown (HTML tetap di-escape). Tampilan lain tidak berubah (Markdown & HTML identik dengan 1.0.7 untuk 4 data uji).
- **`--txt` lebih aman:** path `--txt` sama dengan `--html` → ERROR sebelum menulis apa pun (termasuk file pencatat nomor); `.html`/`.htm` di `--txt` diganti `.txt` (bukan `.html.txt`); folder berakhiran `/` yang belum ada dibuat; folder induk lain yang tidak ada → ERROR sebelum HTML ditulis.
- Tetap: path persis dari baris `BERKAS:` (tidak dikarang), "Info untuk penjual" tidak dikirim ke pembeli, kalimat meterai disalin dari script, nomor +1 dengan file counter.
- 57 uji otomatis lulus (16 uji baru: skenario G24 lengkap di versi teks, angka versi teks = Markdown (kecuali nilai bruto baris berdiskon), PKP+termin+PPh 23, kuitansi DP dengan satu terbilang & meterai, akhiran `.txt` + JSON, tanpa `--txt`, urutan catatan lampir → balasan terakhir, teks pengguna tanpa escape Markdown, HTML PPh 23 tanpa escape Markdown, `--txt` = `--html` ditolak tanpa menulis, `.html` di `--txt` diganti, folder baru dibuat, folder induk tidak ada gagal sebelum HTML ditulis, "kirim file" tidak menjalankan ulang script, catatan MEDIA & lokasi pencatat nomor, versi & aturan balasan di SKILL.md; satu uji lama disesuaikan dengan kalimat catatan baru). **Belum diuji ulang di bot Telegram asli** (perlu pra-cek `uji-tg.sh` lalu satu pesan di bot asli).

## Catatan revisi 1.0.7 (2026-10-14)
Patch kecil dari uji ulang OpenClaw 1.0.6 (rata-rata 8,7, semua angka benar; dua cacat 1.0.5 hilang). Rumus PPN/DPP/diskon/termin tidak berubah.
- **Path lampiran dicetak script.** Setelah menulis HTML, script mencetak `BERKAS: <path absolut>` (`os.path.abspath`) pada baris tersendiri, untuk invoice maupun kuitansi; `--format json` juga mengisi `html_disimpan_ke` dengan path absolut. Penyebab: path relatif membuat agent merangkai path sendiri (sampel uji: `/opt/ochome/.openchome/...` salah ketik, lampiran kuitansi gagal).
- **Lampirkan dulu, tawar kemudian.** SKILL.md: berkas dilampirkan dengan path persis dari baris `BERKAS:` (tidak disusun/ditebak), di semua kanal dan untuk kuitansi juga; tawaran "balas 'kirim file'" hanya bila percobaan lampir gagal. Tabel ringkasan dari script disalin apa adanya (termasuk baris judul). Ditambah blok "UNTUK AGENT SAJA".
- **Catatan meterai dihitung dari angka.** Uji 1.0.6 menemukan agent menulis sisa Rp5.075.000 "di bawah Rp5jt". Script kini menulis sendiri kalimat sisa tagihan: sisa di atas Rp5.000.000 -> "di atas Rp5.000.000 ... wajib bermeterai Rp10.000"; sisa Rp5.000.000 atau kurang -> "tidak lebih dari Rp5.000.000 ... tidak wajib meterai"; untuk invoice bertermin, tiap termin dinilai sendiri. Aturan tetap: wajib bila nilai penerimaan uang lebih dari Rp5.000.000 (tepat Rp5.000.000 tidak wajib). SKILL.md meminta kalimat itu disalin apa adanya.
- 41 uji otomatis lulus (8 uji baru: baris `BERKAS:` absolut untuk invoice, kuitansi, dan JSON; meterai sisa Rp5.075.000, tepat Rp5.000.000, di bawahnya, DP di atas batas, termin). Belum diuji ulang oleh penguji independen di OpenClaw.

## Catatan revisi 1.0.6 (2026-10-14)
Perbaikan tiga cacat kecil dari uji OpenClaw sebelum/sesudah 2026-10-14 (versi 1.0.5: 6,0 -> 8,8, LULUS). Rumus PPN/DPP/termin tidak berubah (semua angka cocok dengan hitungan penguji).
- **Penanda tangan tidak ditebak.** Nama penanda tangan (juga jabatan, nama usaha, alamat, dan "a.n." rekening) hanya diisi bila pengguna menyebutnya langsung; sebelumnya agent pernah memakai nama pemilik rekening sebagai penanda tangan. Tanpa itu, dokumen memakai `[isi nama penanda tangan]`. Script kini tidak menulis "a.n." bila nama pemilik rekening kosong (tidak ada lagi "a.n. " kosong atau tebakan).
- **Nama berkas HTML = nomor di chat.** `--html invoice-{nomor}.html` (atau `--html <folder>`) memberi nama berkas dari nomor invoice yang sama dengan yang tampil di chat (`/` menjadi `-`; `001/INV/X/2026` -> `invoice-001-INV-X-2026.html`, kuitansi -> `kuitansi-KWT-2026-10-0004.html`). Path biasa tanpa `{nomor}` tetap dipakai apa adanya. Script memberi PERHATIAN bila nomor sama dengan nomor terakhir yang disebut pengguna; SKILL.md menegaskan nomor baru tidak pernah mengulang nomor terakhir.
- **Berkas HTML untuk setiap dokumen.** Invoice maupun kuitansi dibuat dan dilampirkan; bila kanal tidak bisa melampirkan, sebut nama berkas dan tawarkan "balas 'kirim file'" (sebelumnya kuitansi hanya disebut path-nya).
- 33 uji otomatis lulus (7 uji baru: nama berkas dari nomor, folder, kuitansi, peringatan nomor sama, "a.n." tidak ditebak, penanda tangan tidak diambil dari rekening). Belum diuji ulang oleh penguji independen di OpenClaw.

## Catatan revisi 1.0.5 (2026-10-13)
- **Nomor invoice tidak dobel lagi saat membuat beberapa invoice berturut-turut.** Temuan uji platform OpenClaw 2026-09-29 (v1.0.1): invoice bernomor sama dengan nomor yang sudah ada. Sejak 1.0.2 script mencetak `Nomor terakhir dibaca: X -> nomor baru: Y` dan SKILL.md mewajibkan nomor terakhir disalin persis, tetapi script belum mengingat nomor yang sudah dibuat: uji ulang 2026-10-13 menunjukkan dua invoice berturut-turut dengan `--nomor-terakhir INV/2026/10/0012` yang sama sama-sama mendapat `INV/2026/10/0013`, dan `--counter-file` yang dipakai bersama `--nomor-terakhir` tidak diperbarui (lalu mulai lagi dari 0001).
- `--counter-file` kini mencatat setiap nomor yang dibuat beserta nama pembeli (`"terbit"`) dan bisa digabung dengan `--nomor-terakhir`/`nomor`: nomor yang sudah dipakai pembeli lain otomatis naik ke nomor berikutnya yang belum terpakai (dengan PERHATIAN), nomor sama untuk pembeli yang sama = revisi (nomor tetap), nomor manual yang bentrok ditolak. Counter per bulan ikut maju dan ditulis aman (file sementara lalu diganti). Lokasi lengkap file counter dicetak agar dipakai file yang sama dari folder kerja mana pun.
- SKILL.md: selalu pakai `--counter-file` di folder kerja yang disepakati; invoice kedua dst. memakai nomor yang baru dibuat script sebagai nomor terakhir.
- Logika hitung (diskon, PPN, PPh 23, meterai, pembulatan) tidak berubah. 26 uji otomatis lulus (7 uji baru penomoran tidak dobel).

## Catatan revisi 1.0.3 (2026-10-01)
- **PPh 23 untuk klien badan yang membayar jasa** (`"pph23": true`): invoice menampilkan potongan PPh 23 2% (4% bila tanpa NPWP) dan **estimasi diterima bersih**, tanpa mengubah total tagihan. Contoh: tagihan Rp14.985.000 (termasuk PPN) → PPh 23 Rp270.000 → diterima bersih Rp14.715.000.
- AI kini menulis invoice lengkap di chat (pengguna Telegram/WhatsApp tidak bisa membuka path file di komputer) dan melampirkan file HTML bila platform mendukung.
- Instruksi: script dijalankan dari subfolder `scripts/` di folder skill. 19 uji otomatis lulus (4 uji baru PPh 23).

## Catatan revisi 1.0.4 (2026-10-01)
- Bila kamu sudah menyebut **PKP**, AI langsung membuat invoice ber-PPN **12% dengan DPP nilai lain 11/12** (PMK 131/2024) dan menyebut asumsinya, tanpa bertanya ulang. Label "PPN 11%" tidak dipakai lagi (temuan uji ulang OpenClaw: agent sempat bertanya "PPN 11%?" padahal member sudah PKP).
- Nomor, kota, dan penanda tangan yang belum disebut cukup diisi placeholder, bukan alasan bertanya.
- Script tidak berubah selain nomor versi; semua tes otomatis lulus.
